  🗣️ 3 Abordagens para Internacionalização

  Opção 1: Next.js i18n nativo (App Router com [lang]) ⭐ Recomendada

  Como funciona: Cada rota fica prefixada com o locale (/pt-BR/..., /en/...). O
  Next.js tem suporte built-in via pasta app/[lang]/. As traduções ficam em
  arquivos JSON por locale.

  Estrutura:
  app/
    [lang]/
      layout.tsx        # Root layout com locale
      page.tsx          # Home
      contato/page.tsx
      grafico/page.tsx
      ...
      dictionaries.ts   # Carrega o JSON do locale
      dictionaries/
        pt-BR.json
        en.json
  proxy.ts (ou middleware.ts)  # Detecta locale pelo header Accept-Language

  Prós:
  - ✅ URLs amigáveis e SEO-friendly (/en/about vs ?lang=en)
  - ✅ Rotas estáticas por locale (melhor performance)
  - ✅ Detecção automática de idioma pelo navegador
  - ✅ Sem bibliotecas externas pesadas
  - ✅ Suporte nativo a generateStaticParams para pré-renderizar todos os
    locales

  Contras:
  - ⚠️ Precisa mover todas as páginas para dentro de app/[lang]/
  - ⚠️ Componentes client-side precisam passar o locale via props/context
  - ⚠️ Middleware/proxy para redirect automático

  ---

  Opção 2: Biblioteca next-intl (mais popular na comunidade)

  Como funciona: Biblioteca especializada que usa a mesma estrutura app/[lang]/
  mas oferece hooks React (useTranslations) e ferramentas de gestão de
  traduções.

  Estrutura:
  app/
    [lang]/
      layout.tsx        # Envolve com NextIntlClientProvider
      page.tsx
      ...
  messages/
    pt-BR.json
    en.json
  i18n/
    routing.ts          # Configuração de locales
    request.ts          # Carrega mensagens no server

  Uso nos componentes:
  // Server Component
  import { getTranslations } from 'next-intl/server';
  const t = await getTranslations('Home');
  <h1>{t('title')}</h1>

  // Client Component
  'use client';
  import { useTranslations } from 'next-intl';
  const t = useTranslations('ContactForm');
  <input placeholder={t('namePlaceholder')} />

  Prós:
  - ✅ API mais ergonômica (t('chave.aninhada') vs acesso manual a objetos)
  - ✅ Suporte a pluralização, formatação de datas/números por locale
  - ✅ Type-safety opcional com TypeScript (autocomplete das chaves)
  - ✅ Ferramentas de developer experience (DX) melhores
  - ✅ Comunidade grande, bem documentado

  Contras:
  - ⚠️ Adiciona dependência (~30kb gzipped)
  - ⚠️ Mesma complexidade de mover páginas para [lang]
  - ⚠️ Requer configuração extra (routing, request config)

  ---

  Opção 3: Context/Estado local (sem mudança de URL) — Sua ideia inicial

  Como funciona: Todo texto passa a ser uma chave (t('home.title')), e um React
  Context provê as traduções baseado em um estado (seletor de idioma no header).
  Sem prefixo de locale na URL.

  Estrutura:
  lib/
    i18n/
      translations.ts   # Objeto com pt-BR e en
      I18nProvider.tsx  # Context + hook useTranslation()
  components/
    LanguageSwitcher.tsx  # Botão PT | EN no header

  Uso nos componentes:
  'use client';
  import { useTranslation } from '@/lib/i18n/I18nProvider';
  const { t, locale, setLocale } = useTranslation();
  <h1>{t('home.title')}</h1>

  Prós:
  - ✅ Menos disruptivo — não precisa mover arquivos, nem adicionar middleware
  - ✅ Troca instantânea de idioma (sem reload da página)
  - ✅ Persistência fácil via localStorage ou cookie
  - ✅ Ideal para portfólio pessoal onde SEO multilíngue não é prioridade

  Contras:
  - ⚠️ URLs não mudam — ruim para SEO e compartilhamento de links (/contato
    mostra PT ou EN dependendo do estado)
  - ⚠️ Conteúdo não é indexável por locale nos motores de busca
  - ⚠️ Default é client-side — todo texto precisa de JavaScript (flash de
    conteúdo não traduzido no primeiro render)
  - ⚠️ Mais difícil de escalar — se crescer muito, a falta de rotas por locale
    vira problema

  📄 JSON puro vs Type-Safety

  JSON puro (mais simples)

  Você cria arquivos JSON e acessa as chaves diretamente:

  // dictionaries/pt-BR.json
  {
    "home": {
      "greeting": "Olá a todos,"
    }
  }

  // dictionaries/en.json
  {
    "home": {
      "greeting": "Hello everyone,"
    }
  }

  // Uso no componente
  const dict = await getDictionary(lang);
  <h1>{dict.home.greeting}</h1>

  Como funciona:
  - Cada locale é um arquivo JSON independente
  - Você acessa via dict.home.greeting (dot notation)
  - Se errar uma chave (ex: dict.home.greting), o erro só aparece em runtime
    (página quebra ou mostra undefined)

  Prós:
  - ✅ Zero configuração extra
  - ✅ Simples de entender e manter
  - ✅ Fácil adicionar novos idiomas (só criar novo JSON)

  Contras:
  - ❌ Erro de digitação só aparece quando a página quebra
  - ❌ Sem autocomplete no VS Code (você precisa lembrar as chaves)

  ---

  Type-Safety (mais seguro, recomendado)

  Você usa o JSON do idioma padrão (pt-BR) como "fonte da verdade" e o
  TypeScript valida todos os outros idiomas contra ele:

  // dictionaries.ts
  import ptBR from './dictionaries/pt-BR.json';

  // O tipo de TRADUÇÃO é inferido do pt-BR
  export type Dictionary = typeof ptBR;

  // Carrega dinamicamente, mas com tipo garantido
  const dictionaries = {
    'pt-BR': () => import('./dictionaries/pt-BR.json').then(m => m.default as
  Dictionary),
    en: () => import('./dictionaries/en.json').then(m => m.default as
  Dictionary),
  };

  O que acontece se você esquecer uma chave no en.json:

  // en.json — esqueceu "greeting"
  {
    "home": {
      "farewell": "Bye"
    }
  }

  O TypeScript erro em compile time:
  Type '{ home: { farewell: string; }; }' is not assignable to type 
  'Dictionary'.
    Property 'greeting' is missing.

  Prós:
  - ✅ Erro de chave faltando aparece antes de rodar (no pnpm build ou no VS
    Code)
  - ✅ Autocomplete no VS Code — você vê todas as chaves disponíveis
  - ✅ Se mudar uma chave no pt-BR, o TypeScript avisa que o en está
    desatualizado
  - ✅ Refatoração segura (renomear chave atualiza todos os lugares)

  Contras:
  - ⚠️ Pequena configuração extra (5 minutos a mais)
  - ⚠️ Se o JSON for muito grande, o TypeScript pode ficar lento (não é problema
    para seu tamanho)

  ---

  💡 Minha recomendação: Type-Safety

  Para um projeto que vai crescer (você vai traduzir todo o conteúdo, incluindo
  case studies longos), o type-safety vai economizar muito tempo. Um erro de
  chave faltando no en.json quebraria a página inteira em produção — com
  type-safety você descobre isso no pnpm build.

  A configuração extra é mínima — basically importar o JSON do pt-BR e usar
  typeof para criar o tipo.

  proxy.ts (novo, na raiz)

  import { NextResponse } from 'next/server';
  import type { NextRequest } from 'next/server';
  import { locales, defaultLocale } from './i18n/config';

  export function proxy(request: NextRequest) {
    const { pathname } = request.nextUrl;

    // Já tem locale? Deixa passar
    const hasLocale = locales.some(
      (locale) => pathname.startsWith(`/${locale}/`) || pathname ===
  `/${locale}`
    );
    if (hasLocale) return;

    // Detecta idioma preferido (cookie > header > default)
    const cookieLocale = request.cookies.get('NEXT_LOCALE')?.value;
    const acceptLang = request.headers.get('accept-language') ?? '';
    const preferred = cookieLocale ??
      (acceptLang.includes('en') ? 'en' : defaultLocale);

    // Redireciona para /pt-BR/... ou /en/...
    request.nextUrl.pathname = `/${preferred}${pathname}`;
    return NextResponse.redirect(request.nextUrl);
  }

  export const config = {
    matcher: ['/((?!_next|images|illustrations|favicon.ico).*)'],
  };

  4. Componentes Modificados

  LanguageSwitcher.tsx (novo)

  'use client';
  import { usePathname, useRouter } from 'next/navigation';
  import { locales, localeNames, type Locale } from '@/i18n/config';

  export function LanguageSwitcher({ currentLocale }: { currentLocale: Locale })
  {
    const pathname = usePathname();
    const router = useRouter();

    const switchLocale = (newLocale: Locale) => {
      // Salva preferência no cookie
      document.cookie = `NEXT_LOCALE=${newLocale}; path=/; max-age=31536000`;
      // Troca o prefixo na URL: /pt-BR/contato → /en/contato
      const newPath = pathname.replace(`/${currentLocale}`, `/${newLocale}`);
      router.push(newPath);
    };

    return (
      <div className="flex gap-2">
        {locales.map((locale) => (
          <button
            key={locale}
            onClick={() => switchLocale(locale)}
            className={locale === currentLocale ? 'font-black' : 'font-normal
  opacity-70'}
          >
            {localeNames[locale]}
          </button>
        ))}
      </div>
    );
  }

  app/[lang]/layout.tsx (modificado)

  import { getDictionary, isLocale } from '@/i18n/dictionaries';
  import { notFound } from 'next/navigation';
  import { Header } from '@/components/layout/Header';
  import { Footer } from '@/components/layout/Footer';

  export async function generateStaticParams() {
    return [{ lang: 'pt-BR' }, { lang: 'en' }];
  }

  export default async function RootLayout({
    children,
    params,
  }: {
    children: React.ReactNode;
    params: Promise<{ lang: string }>;
  }) {
    const { lang } = await params;
    if (!isLocale(lang)) notFound();

    const dict = await getDictionary(lang);

    return (
      <html lang={lang} className="h-full" suppressHydrationWarning>
        <body className="min-h-full flex flex-col" suppressHydrationWarning>
          <Header lang={lang} dict={dict} />
          <main className="flex-1">{children}</main>
          <Footer dict={dict} />
        </body>
      </html>
    );
  }

  3.4. proxy.ts (na raiz do projeto)

  import { NextResponse } from 'next/server';
  import type { NextRequest } from 'next/server';
  import { locales, defaultLocale, type Locale } from './i18n/config';

  const PUBLIC_FILE = /\.(.*)$/;

  export function proxy(request: NextRequest) {
    const { pathname } = request.nextUrl;

    // Ignora arquivos públicos, API, _next
    if (pathname.startsWith('/_next') || PUBLIC_FILE.test(pathname)) {
      return;
    }

    // Já tem locale?
    const pathnameHasLocale = locales.some(
      (locale) => pathname.startsWith(`/${locale}/`) || pathname ===
  `/${locale}`
    );

    if (pathnameHasLocale) return;

    // Detecta locale: cookie > Accept-Language > default
    const cookieLocale = request.cookies.get('NEXT_LOCALE')?.value;
    const acceptLang = request.headers.get('accept-language') ?? '';

    let locale: Locale = defaultLocale;

    if (cookieLocale && locales.includes(cookieLocale as Locale)) {
      locale = cookieLocale as Locale;
    } else if (acceptLang.toLowerCase().includes('en')) {
      locale = 'en';
    }

    // Redireciona para /locale/path
    request.nextUrl.pathname = `/${locale}${pathname}`;
    return NextResponse.redirect(request.nextUrl);
  }

  export const config = {
    matcher: ['/((?!api|_next/static|_next/image|favicon.ico).*)'],
  };

  4.1. lib/i18n/provider.tsx (Client Context)

  'use client';

  import { createContext, useContext, type ReactNode } from 'react';
  import type { Dictionary, Locale } from '@/i18n/dictionaries';

  type I18nContextValue = {
    dict: Dictionary;
    locale: Locale;
  };

  const I18nContext = createContext<I18nContextValue | null>(null);

  export function I18nProvider({
    dict,
    locale,
    children,
  }: {
    dict: Dictionary;
    locale: Locale;
    children: ReactNode;
  }) {
    return (
      <I18nContext.Provider value={{ dict, locale }}>
        {children}
      </I18nContext.Provider>
    );
  }

  export function useI18n() {
    const ctx = useContext(I18nContext);
    if (!ctx) throw new Error('useI18n must be used within I18nProvider');
    return ctx;
  }

  type Path<T, P extends string = ''> = T extends string
    ? P
    : T extends object
      ? {
          [K in keyof T & string]: Path<T[K], P extends '' ? K : `${P}.${K}`>;
        }[keyof T & string]
      : never;

  export type TranslationKey = Path<Dictionary>;

  // Hook com autocomplete
  export function useTranslations() {
    const { dict, locale } = useI18n();

    const t = (key: TranslationKey): string => {
      const value = key.split('.').reduce<unknown>((obj, k) => {
        if (obj && typeof obj === 'object' && k in obj) {
          return (obj as Record<string, unknown>)[k];
        }
        return undefined;
      }, dict);

      if (typeof value !== 'string') {
        console.warn(`Missing translation: ${key} (locale: ${locale})`);
        return key;
      }
      return value;
    };

    return { t, locale, dict };
  }

  // Helper para Server Components
  export function createTranslator(dict: Dictionary, locale: string) {
    return (key: TranslationKey): string => {
      const value = key.split('.').reduce<unknown>((obj, k) => {
        if (obj && typeof obj === 'object' && k in obj) {
          return (obj as Record<string, unknown>)[k];
        }
        return undefined;
      }, dict);

      if (typeof value !== 'string') {
        console.warn(`Missing translation: ${key} (locale: ${locale})`);
        return key;
      }
      return value;
    };
  }

  'use client';

  import { usePathname, useRouter } from 'next/navigation';
  import { locales, localeNames, type Locale } from '@/i18n/config';

  export function LanguageSwitcher({ currentLocale }: { currentLocale: Locale })
  {
    const pathname = usePathname();
    const router = useRouter();

    const switchLocale = (newLocale: Locale) => {
      // Salva preferência no cookie (1 ano)
      document.cookie = `NEXT_LOCALE=${newLocale}; path=/; max-age=31536000;
  SameSite=Lax`;

      // Troca o prefixo: /pt-BR/contato → /en/contato
      const segments = pathname.split('/');
      segments[1] = newLocale;
      const newPath = segments.join('/');

      router.push(newPath);
      router.refresh();
    };

    return (
      <div className="flex items-center gap-1 rounded-full 
  bg-[color:var(--color-blue-soft)]/30 p-1">
        {locales.map((locale) => (
          <button
            key={locale}
            onClick={() => switchLocale(locale)}
            aria-label={`Mudar para ${localeNames[locale]}`}
            aria-pressed={locale === currentLocale}
            className={`rounded-full px-3 py-1 text-sm transition-all ${
              locale === currentLocale
                ? 'bg-[color:var(--color-blue)] text-[color:var(--color-cream)]
  font-bold'
                : 'text-[color:var(--color-blue)]
  hover:bg-[color:var(--color-blue-soft)]/50 font-normal'
            }`}
          >
            {localeNames[locale]}
          </button>
        ))}
      </div>
    );
  }

  export function getLocalizedProject(
